# Specification

本文件是範圍與成功標準的唯一正式來源，回答「要完成什麼」。安裝、執行與快速使用方式放在 `README.md`；實作方法放在 `architecture.md`。

## Problem and Motivation

- Problem：現有 Git GUI 工具幾乎都在呈現「已經發生的歷史」，但使用者實際會卡住的是「我不知道別的地方發生了什麼、也不知道我接下來的動作會造成什麼結果」。具體有三個缺口：
  1. 同時管理多個 repository 時，沒有一個地方能一眼看出哪些專案需要處理。
  2. 遠端已經有新的變更時，工具不會主動告知；`pull` 之前也看不到即將進來的內容。
  3. 本機與遠端分岔（diverge）之後，工具只丟出 merge / rebase 兩個選項，使用者無法預知結果、不知道安不安全、出錯後不知道怎麼回復。
- Motivation：這三件事在單人跨設備開發時特別常見（在 A 機器忘記推送，到 B 機器繼續做而分岔），而現有工具沒有針對此情境設計。另有效能問題：Sourcetree 在使用者實際使用中會卡頓。
- Users / use cases：
  - 主要：單一開發者同時管理多個 repository，並在自己的多台設備（Windows 與 Linux）之間切換工作。
  - 次要：與他人協作的團隊專案。團隊專屬功能（PR、review、CI 整合）本階段不納入。

## Goals

- 提供多 repository 狀態總覽，使用者不需逐一開啟即可知道哪些專案有待處理事項。
- 在背景偵測遠端更新並通知使用者。
- 在執行 `pull` 之前，讓使用者看到即將進來的變更內容，以及是否會與本機修改衝突。
- 在本機與遠端分岔時，讓使用者能預先看到不同處置方式的結果、得到明確建議，並在事後可回復。
- 單一 repository 的歷史圖能清楚辨識分支走向。
- 效能明顯優於 Sourcetree，且常駐執行時資源占用可接受。

## Inputs and Outputs

- Input：
  - 本機檔案系統上的 Git repository（數量：多個，實際上限待確認）。
  - 遠端 Git 主機，透過 SSH 金鑰認證。
  - 使用者設定（監控哪些 repository、檢查頻率、通知偏好）——具體格式待確認。
- Output：
  - 圖形介面：多 repo 總覽、單一 repo 歷史圖、變更預覽、分岔預覽。
  - 系統通知。
  - 對使用者 repository 的 git 操作（fetch、pull、merge、rebase 等），皆須使用者確認後執行。
- Error cases：
  - SSH 金鑰未解鎖或認證失敗：必須明確顯示狀態，不得靜默失敗。
  - 遠端無法連線：必須顯示最後成功檢查時間。
  - Repository 損壞、路徑消失、非 git 目錄：明確報錯並允許移除該項目。
  - 操作進行中（rebase / merge 未完成）的 repository：必須正確辨識並顯示當前狀態。

## Scope

### In Scope

- 多 repository 狀態總覽（待拉取／未推送／未提交／乾淨）。
- 背景定期 fetch，SSH 金鑰認證，含明確的失敗狀態顯示。
- 遠端更新通知。第一版採系統彈出通知；觸發條件的細緻化留待實際使用後評估。
- Pull 前預覽：即將進入的 commit、影響的檔案、與本機未提交變更的重疊偵測。
- 分岔處理：
  - 預先計算兩邊變更是否有檔案層級重疊（即是否可能衝突）。
  - 以圖示方式呈現 merge 與 rebase 兩種處置的結果差異。
  - 依情境提供明確建議。
  - 提供可回復的路徑。
- 單一 repository 歷史圖：分支繪製為直線、同一分支顏色穩定、分支名稱標示於線上。
- 基本 Git 操作功能。具體項目見下方「基本功能清單」。
- 目標平台：Windows 與 Linux。

### 基本功能清單

「基本功能都要有」的具體展開。分級依據是「缺少此項時，使用者是否無法把本程式當作日常工具」，而非開發難度。分級由開發方提出，尚待使用者確認。

創新功能（多 repo 總覽、背景偵測、變更預覽、分岔處置）列於上方 In Scope，不重複列出。兩者的關係是：基本功能是入場條件，創新功能是採用理由。

下列標記說明目前狀態：**[已完成]** 表示已實作並有測試涵蓋。

#### P0 — 缺少即無法作為 Git 客戶端使用

- **[已完成]** Repository 管理：加入、移除、開啟；多 repository 清單。
- **[已完成]** 狀態檢視：目前分支、未提交的變更、相對於遠端的領先與落後數量。
- 變更檢視：異動檔案清單 **[已完成]**；差異呈現的並排與行內模式尚未實作。
- 暫存操作：檔案層級的 stage / unstage **[已完成]**；hunk 與單行層級的部分暫存尚未實作。
- **[已完成]** 提交：建立 commit、修改前一次 commit（amend）、輸入與編輯提交訊息。
- 分支操作：列出、建立、切換 **[已完成]**；刪除、重新命名、設定追蹤分支尚未實作。
- **[已完成]** 遠端同步：fetch、pull（快轉）、push。強制推送僅提供 force-with-lease 語意：
  推送前重新查詢遠端位置，與本機記錄不符即中止。
- **[已完成]** 合併與衝突解決：執行 merge 與 rebase；提供衝突解決介面
  （雙方內容並列、整檔擇一、或直接編輯合併結果）；可繼續、略過或中止。
- 歷史檢視：commit 圖形 **[已完成]**；commit 詳細內容與單一檔案的變更歷史尚未實作。
- Stash：建立、取出、刪除 **[已完成]**；僅暫存部分變更尚未實作。
- **[已完成]** 認證：整合系統既有的 SSH agent 與 credential helper；
  認證失敗與網路失敗分開回報。

#### P1 — 缺少則專業使用者無法完整工作

- 互動式 rebase：調整順序、squash、fixup、edit、drop、reword。尚未實作。
  （整段 rebase 到遠端之上已完成，見 P0。）
- cherry-pick、revert。
- reset：三種模式（soft / mixed / hard），介面須明確說明各自的後果。
- **[已完成，做法不同]** 復原：不採用 reflog 檢視，改為在每次危險操作前自動建立
  還原點，並提供一鍵還原。設計理由見 `architecture.md`。
- blame 檢視，支援跨檔案改名追蹤。
- Tag：列出、建立、刪除、推送。
- 搜尋：依提交訊息、檔案內容、作者、檔案路徑。
- `.gitignore` 編輯與套用。
- Patch 匯入與匯出。

#### P2 — 之後再評估

- Worktree 管理。
- Submodule 支援。
- Git LFS。
- Sparse-checkout、partial clone。
- Hooks 檢視與啟用停用。
- 命令面板與全鍵盤操作。
- 佈景主題。

#### 實作順序上的限制

- P0 的「歷史檢視」與創新功能中的「分岔處置」共用同一套圖形佈局程式，應一併設計。
- P1 的「互動式 rebase」與「reflog 復原」是分岔處置功能的延伸，實作順序應在分岔處置之後。
- P0 的認證與 fetch 是背景偵測功能的前置條件。

### Out of Scope

- 自建後端服務或使用者帳號系統。使用者已明確排除，理由是不願維護伺服器。
- 跨裝置同步「尚未推送的工作狀態」。此功能在無後端的前提下技術上不可行（Git 無法得知另一台機器上未推送的內容），已與使用者確認取捨。
- 平台整合（GitHub / GitLab 的 PR、review、CI 狀態）。
- 團隊協作專屬功能。
- macOS 支援。

## Requirements and Constraints

- Functional：見上方 In Scope。
- Performance：
  - 需明顯優於 Sourcetree（使用者實際體驗為「有點卡」）。具體量測基準待確認。
  - 常駐系統列執行，閒置資源占用需可接受；具體上限待確認。
  - 同時背景監控多個 repository 時不得阻塞介面。
- Correctness / reliability：
  - 任何會改寫歷史或丟棄工作成果的操作必須先確認並可回復。
  - 背景 fetch 失敗必須可見，不得讓使用者誤以為仍在監控中。
- Compatibility：
  - 平台：Windows 與 Linux。開發環境為 Ubuntu 24.04 x86_64。
  - Windows 版無法於 Linux 交叉建置，需實體 Windows 環境或 CI。
- Security / privacy：
  - 不蒐集、不上傳任何使用者資料。所有資料留在本機。
  - SSH 金鑰由系統既有機制管理（ssh-agent 等），應用程式不自行儲存金鑰或密語。
  - 不得將任何憑證寫入設定檔或紀錄檔。

## Success Criteria

下列項目的後端邏輯皆已實作並有測試涵蓋，但凡是需要在圖形介面上確認的，
在介面能於實體桌面環境顯示之前都不標記為完成 —— 「有測試」與
「使用者真的能用」不是同一件事。


- [ ] 能加入多個 repository 並在單一畫面顯示各自狀態，狀態與實際 `git status` / ref 比對一致。
- [ ] 背景 fetch 能在 SSH 金鑰認證下運作；認證失敗時狀態明確可見。
- [ ] 遠端有新 commit 時能發出通知。
- [ ] Pull 前能列出即將進入的 commit 與受影響檔案，並正確標示與本機未提交變更重疊的檔案。
- [ ] 分岔情境下，能正確判斷兩邊變更是否有檔案重疊，並以圖示呈現 merge 與 rebase 的結果差異。
- [ ] 執行分岔處置後存在可回復路徑，且經實際操作驗證有效。
- [ ] 歷史圖在實際使用的 repository 上能清楚辨識分支走向。
- [ ] 效能與 Sourcetree 的比較有實際量測結果（基準與方法待定義）。
- [x] 分岔情境下可實際執行 rebase 或 merge，衝突可在介面中解決，並可中止或還原。
- [ ] P0 基本功能全數可用。目前差異呈現、hunk 層級暫存、分支刪除與重新命名尚未實作。

## Open Questions

### 已解決

- [x] 前端框架：不使用框架與打包工具，純 HTML/CSS/JS。理由見 `architecture.md`。
- [x] Git 存取方式：採用 `git2`。日後若需要可換成 gitoxide，所有 git 存取
      已集中在少數模組後面。
- [x] 歷史圖繪製方式：canvas 畫線道，HTML 排文字。
- [x] 設定檔：JSON，位於系統設定目錄下的 `dev.gitview.desktop/settings.json`。
- [x] Repository 如何加入：資料夾選擇器手動指定。掃描資料夾尚未提供。
- [x] 復原機制：以自動還原點取代 reflog 檢視。
- [x] 衝突解決的深度：並列雙方內容 + 整檔擇一 + 編輯合併結果；
      不做逐區塊挑選。
